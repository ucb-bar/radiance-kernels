# gemm_mxgemmini

MX-Gemmini GEMM drivers and the fp8/fp4/fp6 **precision + shape ladder** used to
characterize the mesh. Each `mxgemm.*.cpp` is a standalone kernel with its own
`main()`; `common.mk` builds **one `.soc.elf` per `MU_SRCS` entry**, so `make`
produces one binary per config.

The `*.fullout.cpp` ladder covers fp8 and fp4 at `K = 2048` and `K = 5632`, and fp6 at `K = 2048`,
with `128x128` output tiles, plus smaller single-tile and requant configs. Data
headers (`mxgemm.data.<fmt>.m<M>n<N>k<K>.h`) carry operands, e8m0 scales, and the
golden, generated by `gen_mxgemm_data.py` from the in-repo `mx_golden`
(`lib/golden`).

## Tile feasibility

A `128x128` output tile needs `TILE_K <= 128`: the double-buffered A/B operands plus
the `2048`-row C accumulator must all fit in the scratchpad, which
`mxgemm_lib.hpp`'s `C_FITS_IN_SPAD` static_assert enforces at compile time. The
`tk256` / `tk512` fullout configs are therefore infeasible and are excluded from the
build (the `tk128` drivers are the feasible replacements).
