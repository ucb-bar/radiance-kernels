# fa_mx_hostsf -- A/B sandbox for the Rocket-host offload campaign

`flash_attention_mx.cpp` and `flash_mx_impl.hpp` here are a **frozen snapshot** of the main
`kernels/flash_attention_mx/` versions (taken 2026-07-26, md5 2a775d23.../367ae0a6...).  Two other
agents were editing those two files continuously while this campaign ran, and `/tmp/fa_build.sh`
injects `#define`s into the shared source in place -- so an A and a B build made 30 minutes apart
in the main directory are not necessarily the same kernel.  Freezing them is what makes the
steady-state slope table in the commit message an apples-to-apples comparison.

`host.cpp` and `mxgemm_core.hpp` are NOT frozen: the build script copies them from
`kernels/flash_attention_mx/` on every invocation, so the main directory stays the single source
of truth for the two files this campaign owns.

Build/run/measure (build script `/tmp/hs_build.sh`, runner `/tmp/hs_run.sh`, parser
`/tmp/hs_extract.py`):

    bash /tmp/hs_build.sh <TAG> "FULL_ATTN2 FA_STEADY FA_NT4 FA_NOSCALES FA_HOSTHS FA_HOSTCFG"
    bash /tmp/hs_run.sh   <TAG> 900000
    python3 /tmp/hs_extract.py <TAG>          # marks, steady slope, host diag, CPROF
    python3 fa_verify_out.py /tmp/hsruns/<TAG>.out --base 0x40040000 --nbytes 0x4000 \
        --golden golden_O_u16.npy --rows 64 --cols 128 --elem-bytes 2   # 3.5666% == CORRECT

Goldens and `include/fa_data.h` are not committed here (they are byte-identical to the main
kernel directory's and are regenerated by `fa_gen_data.py` / `fa_gen_goldens.py`).
